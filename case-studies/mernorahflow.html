MERNORAHFLOW

An internal operating platform connecting relationships, proposals, project delivery, billing and support.

TypeScriptFastifyPrismaPostgreSQLCloudflare Workers

THE PROBLEM

What needed solving.

When operational data is spread across disconnected tools, following an enquiry through delivery and support becomes difficult. MERNORAHFLOW was designed around one linked business lifecycle while keeping workspaces separate.

MY CONTRIBUTION

What I worked on.

  • Implemented and refined API workflows and PostgreSQL/Prisma data models supporting operational records.
  • Worked on workspace-aware access boundaries, input validation and reliable transitions between connected records.
  • Investigated application and deployment defects; configured a Cloudflare Worker API connected to hosted PostgreSQL.

The web application communicates with an API that applies validation and authorization before updating workspace-scoped PostgreSQL records. Related entities remain connected across the business lifecycle. The operational data stays in MERNORAHFLOW; adjacent intelligence systems do not replace it as the source of truth.

ENGINEERING JUDGMENT

Decisions and trade-offs.

01

Workspace isolation

Records must be scoped to the correct workspace at the API/data-access boundary, not only filtered in the browser.

02

Lifecycle consistency

Represent relationships, projects and billing as linked records rather than unrelated form submissions.

03

Cloud integration

Deploy the API at the edge while using a managed relational database; diagnose connection and configuration faults explicitly.
